# F3 三缓冲预读（消除切图等待）

日期：2026-10-28
涉及：`SD/sd_card_bmp.v`、`top_signage.v`
关联台账：`doc/perf_log.md`（本条属功能改动，不改变时序基线 E1）

---

## 1. 要解决的问题

自动轮播设成每张停留 3 秒后，卡里那张 1920×1080 的图（5.93MB / 12150 扇区）
读一次要 2 秒量级（25MHz SPI 理论 1.99s，叠加 SD 卡内部忙等通常 2.2~2.6s）。
双缓冲下"读下一张"只能等当前图开始切了才做，于是观感是：

```
显示 A ──3s──> [ 干等 2.4s，屏幕还是 A ] ──> 转场 1.1s ──> 显示 B
                 实际停留 5.4s
```

用户要的是**视觉上严格 3 秒一张**，而 SD 卡那边没有提速空间：
`SPI_HIGH_SPEED_DIV = 0` 已经把分频压到 /4 = 25MHz，再往上（50MHz）超出
SD 卡 SPI 模式规范，会加重本来就存在的偶发丢扇区问题。

## 2. 方案：加第三块 SDRAM 缓冲，把读卡藏进停留期

```
t=0.0   A 上屏 + 立刻后台预读 B
t=2.4   B 写好，挂起（pre_ready=1），屏幕仍是 A，用户无感
t=3.0   dwell 到点，只改 disp_buf_idx 指针 → 转场，零等待
        同时后台预读 C
```

关键前提（都已核实）：

| 项目 | 实测值 | 结论 |
|---|---|---|
| SDRAM 容量 | 2M words = 8MB，两帧占 29.3% | 开 3 块后 43.9%，余 4.48MB |
| 读写带宽 | 读 73 MB/s + 写 73 MB/s，合计 147 MB/s | 占 500MB/s 的 29% |
| 地址通道 | `frame_read_write` 原生有 `read_addr_2/3`、`write_addr_2/3`，索引 2 位 | 只是过去接成 0，不用改子模块 |
| 块内偏移 | 翻转 `VFLIP_FIRST_ADDR_OFFSET = 479×640 = 306560` | BUF2 起点 614400 + 306560 = 920960 < 921600，不越界 |

### 块号分配的硬约束

写目标必须同时满足：**≠ 当前显示块**、**≠ 转场正在淡出的旧块**。
`next_buf_lut` 改成 0→1→2→0 轮转即天然满足：

| disp | 预读写 | 转场读 | 冲突 |
|---|---|---|---|
| 0 | 1 | （0→1 时读 0、1） | 无 |
| 1 | 2 | （1→2 时读 1、2） | 无 |
| 2 | 0 | （2→0 时读 2、0） | 无 |

## 3. 改了什么

### `sd_card_bmp.v`

| 位置 | 改动 |
|---|---|
| 新增 `pre_ready / pre_buf / pre_idx / swap_on_commit` | 预读完成但未上屏的那一帧的暂存 |
| `next_buf_lut` | 双块互换 → 三块轮转 0→1→2→0 |
| commit 分支 | 拆成 `load_frame_done`（整帧写好）和 `load_commit_now`（真正上屏）。后台预读只置 `pre_ready`，不动 `disp_buf_idx` |
| 加载调度 | 三条路径：① `swap_now` 指针切换上屏 ② 手动/首图现读后立即上屏 ③ 上屏后立即启动后台预读 |
| `auto_cnt` 计时 | **去掉 `!load_busy` 门控**，改从上屏时刻起算；到点若未预读好则停在终点等待 |
| `settle_cnt` | 600ms → 50ms（防撕裂职责随双缓冲一起消失，只剩 CDC 余量） |
| 门控 `!disp_busy` | 全部移除（写目标已不可能撞上转场读的块） |
| `switch_latency.commit` | 改用 `load_frame_done`，量的是真实读图耗时而非零耗时的指针切换 |

### `top_signage.v`

| 位置 | 改动 |
|---|---|
| 新增 `BUF2_ADDR = FRAME_PIXELS * 2` | 614400 |
| `read_addr_2` / `write_addr_2` | `24'd0` → `BUF2_ADDR` |
| 新增 `disp_buf_prev` | 在 `disp_buf_idx` 变化那一拍锁存旧值 |
| `buf_old_lock`（两处） | `(disp==0)?1:0` → `disp_buf_prev`。原式在三缓冲下会把新图当旧图淡出 |

## 4. 附带修好的问题

加载失败的重试现在发生在**后台**：屏幕上是当前图，读错了就重试，
撕裂、卡顿、跳图全部不可见。之前"长延迟后直接跳到第一张"的观感消失
（拉黑与回绕逻辑本身未改，只是不再影响画面）。

## 5. 上板验证清单

烧录后按顺序看：

1. **常规轮播**：KEY1 开自动播放，4 张图应严格约 3.0s 一张（含 1.1s 转场，
   即从一张图出现到下一张图开始变白约 3s）。1080P 那张不应再有额外停顿。
2. **转场正确性**（重点，本次最高风险项）：每次淡出的是**上一张图**，
   不是新图。若看到"硬切一下再白一下再淡入"，说明 `buf_old_lock` 取错了块
   —— 检查 `disp_buf_prev` 锁存。
3. **无撕裂**：转场淡出段不应出现推进的横条噪点。若出现，说明预读写到了
   正在被读的块。
4. **KEY0**：单按应立即切换（预读命中时不经过加载）；连按两次不应跳两张以上。
5. **DIG1**（`DIG_SEL=3` 诊断模式）：多数应为 2。出现 3/4/5 说明后台读失败，
   此时屏幕应**无感知**（这正是预读的收益）。
6. **反复上电 5 次**：验证 SD 初始化偶发问题（沿用 `doc/E1_bringup_check.md`）。
7. **OSD 切图耗时**：`load` 一项应显示真实读图时间（1080P ≈ 2.2~2.6s），
   而不是 0 或 9.99 饱和值。

## 6. 回退方法

改动集中在两个文件，回退只需恢复这两份：

```bash
git --git-dir=.git_old_20261025 show a65e975:src/user_source/hdl_source/SD/sd_card_bmp.v \
  > src/user_source/hdl_source/SD/sd_card_bmp.v
git --git-dir=.git_old_20261025 show a65e975:src/user_source/hdl_source/top_signage.v \
  > src/user_source/hdl_source/top_signage.v
```

注意 `a65e975` 是 E1 基线提交，回退会连带丢掉 10-28 那两处改动
（失败诊断细分、AUTO_DWELL_SEC 参数）。若只想退三缓冲，
应由提交历史里取"F3 之前"的那一版。

## 7. 未解决 / 后续可做

- 若某张图读取超过停留时间，那一次会顺延（物理极限，无法靠改逻辑消除）。
  真要根治只能降源图分辨率，或把 SPI 提到 50MHz（有丢扇区风险，暂不做）。
- 第四块缓存的地址通道（`read_addr_3`/`write_addr_3`）仍接 0，留着备用。
- `sd_card_clk` 域 −3.736ns 的时序违例与本次改动无关，仍待处理。
