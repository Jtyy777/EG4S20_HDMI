# 数字标牌信息发布终端（info_signage）—— 赛道一差异化设计方案

> 面向 2026 全国大学生嵌入式芯片与系统设计竞赛 · FPGA 赛道  
> 赛道一：基于安路 EG4S20 的 HDMI 多媒体播放系统  
> 目标板：EG4S20 综合底板 + DMZ_EG4S20 口袋核心板（芯片 EG4S20BG256）

---

## 一、设计定位与差异化总览

样例工程 `lab_ex4_tf`（TF 卡 BMP 轮播）只实现了**视频显示**，顶层里 HDMI 音频端口全部接 0（无音频），无任何扩展特效。本方案以「**数字标牌信息发布终端**」为场景，在复用底层平台 IP 的基础上，**重构顶层流水线并新增 13 个纯自研模块**，完整覆盖赛道一的**基础要求 + 全部 5 项扩展加分项**。

### 与样例的本质区别

| 维度     | 样例 lab_ex4_tf | 本方案 info_signage                |
| ------ | ------------- | ------------------------------- |
| 音频输出   | ❌ 无（端口接 0）    | ✅ HDMI 音频（I2S 测试音 → ARC → TMDS） |
| 转场特效   | ❌ 无           | ✅ 旧图褪白 → 白场 → 新图淡入（64 帧）        |
| OSD 叠加 | ❌ 无           | ✅ 滚动字幕 + 图片计数 + 参数与耗时读数          |
| 参数调节   | ❌ 无           | ✅ 亮度/对比度实时调节 + OSD              |
| 音频可视化  | ❌ 无           | ✅ 8 段频谱柱状图叠加                    |
| 交互方式   | 2 个独立按键       | 4×4 矩阵键盘（8 个功能键）                |
| 源图尺寸   | 固定 640×480    | 任意尺寸，写侧等比缩放 + 非 4:3 补边           |
| 帧缓存    | 双缓冲           | 三缓冲，读卡与上屏提交解耦                   |
| 顶层架构   | 单一读图→显示       | 多级图像处理流水线                       |

## 二、数据流水线架构

```
写侧（sd_card_clk 100 MHz）
TF 卡读图 (sd_card_bmp / bmp_read)
        │  SD 卡 SPI
        ▼
等比缩放 (img_scaler)  ← 自研（双线性，居中补黑边）
        │
        ▼
SDRAM 三缓冲 (frame_read_write + sdram)

显示侧（video_clk 25 MHz）
SDRAM 三缓冲
        │
        ▼
像素坐标生成 (pixel_coord_gen)  ← 自研
        │
        ▼
转场特效 (transition_effect)  ← 自研（旧图 → 白场 → 新图）
        │
        ▼
亮度/对比度调节 (brightness_contrast)  ← 自研（参数经 param_cdc 跨域）
        │
        ▼
频谱柱状图叠加 (spectrum_overlay)  ← 自研
        │
        ▼
OSD 字幕与信息层 (osd_overlay)  ← 自研
        │
        ▼
RGB→AXIS (video_rgb_to_axis_640x480)
        │
        ▼
HDMI 1.4b 发射（视频 + 音频）
```

音频链路：`PLL_HDMI_AUDIO(12.29MHz MCLK) → hdmi_audio_tone_i2s_64fs(I2S 八音测试源) → I2S_receiver → audio_arc_calculate(ARC) → HDMI 发射核`，同时 `audio_spectrum` 从 PCM 样本实时计算八频点频谱。

帧缓存为**三块**（2026-10-28 由双缓冲升级）：写入目标、当前显示、正在淡出的旧图各占一块，读卡在后台完成，与上屏提交解耦。`pre_ready` 只表示「整帧已写好」，真正换块由轮播到点或手动请求触发。

## 三、自研模块清单（13 个，纯原创代码）

| 模块       | 文件                      | 功能                                     | 对应加分项     |
| -------- | ----------------------- | -------------------------------------- | --------- |
| 转场特效引擎   | `transition_effect.v`   | 旧图褪白 30 帧 + 白场 4 帧 + 新图淡入 30 帧，像素级 alpha 混合，单读通路 | ② 转场特效    |
| 写侧缩放     | `img_scaler.v`          | 任意分辨率等比双线性缩放到 640×480，非 4:3 居中补黑边，RGB 三拍复用插值 | ③ 图片缩放    |
| 亮度/对比度调节 | `brightness_contrast.v` | 8.8 定点亮度偏移 + 对比度缩放，逐通道 clamp           | ④ 实时参数调节  |
| OSD 字幕与信息层 | `osd_overlay.v`         | 5×7 ASCII + 16×16 汉字点阵；滚动字幕、图片计数、亮度/对比度及 T/W/L 读数 | ① 图层叠加/字幕 |
| 音频频谱分析   | `audio_spectrum.v`      | 八频点 Goertzel 递推 + 相对幅度量化               | ⑤ 音频可视化   |
| 频谱柱状图叠加  | `spectrum_overlay.v`    | 频谱柱高→绿红渐变柱状图，左下角无黑框叠加                  | ⑤ 音频可视化   |
| 矩阵键盘扫描   | `keypad_scanner.v`      | 4×4 矩阵键盘扫描 + 去抖 + 按下脉冲/按住电平双输出         | 交互控制      |
| 参数控制器    | `param_controller.v`    | 按键事件 → 亮度/对比度/自动播放/OSD 显隐，长按连发          | ④ 实时参数调节  |
| 参数跨域同步   | `param_cdc.v`           | 亮度/对比度 50 MHz → 25 MHz 整组传递，翻转握手         | 流水线基础设施   |
| 像素坐标生成   | `pixel_coord_gen.v`     | 从 de/vs 重建 640×480 像素坐标                | 流水线基础设施   |
| 4 位数码管驱动 | `seg4_driver.v`         | 适配核心板共阴 4 位数码管，200 Hz 整屏刷新             | 调试/状态显示   |
| I2S 测试音源 | `hdmi_audio_tone_i2s_64fs.v` | 由 MCLK 直接生成 BCLK/LRCK/DOUT，C4~C5 八音循环 | 音频链路      |
| 并行 PCM 测试源 | `hdmi_audio_tone_pcm_scale.v` | 与上者等价但不产生 I2S 时序，当前未例化，留作对比     | 备用        |

另有一批平台模块在 `rtl/` 内做适配改造：`I2S_receiver.v`、`audio_arc_calculate.v`、`startup_pulse.v`、`video_rgb_to_axis_640x480.v`。

## 四、按键交互定义（4×4 矩阵键盘）

核心板矩阵键盘 KEY0~KEY15，本方案使用前 8 个：

| 按键   | 位置        | 功能                          |
| ---- | --------- | --------------------------- |
| KEY0 | Row0·Col0 | 手动切下一张图片                    |
| KEY1 | Row0·Col1 | 自动播放 开/关（上电默认关，间隔 3 s）      |
| KEY2 | Row0·Col2 | 亮度 +4（长按连发）                 |
| KEY3 | Row0·Col3 | 亮度 −4（长按连发）                 |
| KEY4 | Row1·Col0 | 对比度 +0.03125×（长按连发）         |
| KEY5 | Row1·Col1 | 对比度 −0.03125×（长按连发）         |
| KEY6 | Row1·Col2 | 恢复默认参数                      |
| KEY7 | Row1·Col3 | OSD 信息层显隐（左上 `L:/C:` 与右上 `T:/W:/L:` 一起切换），上电默认隐藏；字幕与右上图片计数不受影响 |

> 关掉 OSD 读数后，KEY2~KEY5 的调节依然对画面生效，只是看不到数值。
> KEY7 只切换显示，不改任何参数；再按一次即恢复显示。
> 原「切换转场类型」键已删除，转场固定为白场过渡，键位因此整体前移一位。

数码管（`DIG_SEL = 3`）在非加载状态从左到右显示：最近按下的键号、读卡状态码、加载诊断码、图片总数；加载诊断为 1 时后三位显示 `ddd`。键号只记录 KEY0~KEY6，KEY7 是纯显示开关，不更新键号。

## 六、评分点对应关系

| 赛道一要求                  | 实现情况                 |
| ---------------------- | -------------------- |
| 基础：FPGA 自主实现全部逻辑（无处理器） | ✅ 纯 RTL，无软核          |
| 基础：BMP 解析 + SDRAM 帧缓存  | ✅ 写入三缓冲，读卡与上屏解耦 |
| 基础：HDMI 视频输出           | ✅ HDMI 1.4b 640×480  |
| **基础：HDMI 音频输出**       | ✅ 补全样例缺失项            |
| 基础：交互控制                | ✅ 矩阵键盘               |
| 加分 ① 图层叠加/字幕           | ✅ OSD 滚动字幕 + 计数      |
| 加分 ② 转场特效              | ✅ 旧图褪白 → 白场 → 新图淡入 |
| 加分 ③ 图片缩放              | ✅ 写侧双线性，任意尺寸适配 640×480   |
| 加分 ④ 实时参数调节 + OSD      | ✅ 亮度/对比度 + OSD 数值    |
| 加分 ⑤ 音频可视化             | ✅ 频谱柱状图              |

> 缩放放在写侧完成：素材加载时一次性适配到 640×480，显示侧始终按统一分辨率读帧，刷新时不再为插值额外取源像素。

## 八、编译与部署注意事项

### 快速开始（TD 工程已就绪）

1. **打开工程**：用安路 TD 软件（6.2+，支持 EG4S20BG256）直接打开  
   `src/td_project/info_signage_v1.0.al`，即可加载全部源文件、约束和 IP 配置。
2. **综合 + 布局布线**：工程内已配置 `syn_1`（综合）和 `phy_1`（布局布线）两个 Run，直接 Run All 即可。
3. **烧录**：生成的 `.bit` 文件烧录到核心板配置 Flash 或直接下载运行。

### 关键说明

1. **FIFO IP**：`frame_read_write.v` 依赖的 `wfifo_32_32_512`、`rfifo_32_32_512` 由  
   `IP/afifo_16_32_256.ipc`、`IP/afifo_32_16_256.ipc` 提供（TD 综合时自动生成，无需手动创建）。
2. **PLL IP**：`sys_pll`、`video_pll` 的 `.ipc` 在 `IP/` 目录，`PLL_HDMI_AUDIO` 在 `td_project/al_ip/`，均已配置。
3. **时钟**：核心板 50MHz 晶振（R7），与样例完全一致，PLL 参数无需修改。
4. **include 路径**：`SD/sdram.v` 内 `include "../user_source/hdl_source/include/global_def.v"`，  
   若 TD 报找不到文件，请在工程设置里把 `src/user_source/hdl_source/include` 加入 include 搜索路径  
   （与样例工程的配置一致）。
5. **TF 卡图片**：不再要求 640×480。`img_scaler` 会把任意尺寸等比缩放到 640×480，非 4:3 素材居中补黑边。推荐 24/32 位无压缩、自底向上的 BMP（32 位忽略 alpha）。根目录**只放 4 张**，`bmp_read` 按目录项顺序取前 4 个 `.BMP`，多放会被排进轮播队列。素材与转换脚本见 `doc/sd_images/`。

## 九、当前构建状态

以下数字取自 `best_result` 与 `phy_1`，与仓库内的 bit 同源（2026-11-03 12:50 综合布线）。

| 项目 | 值 |
|---|---|
| 位流 | `info_signage_v1.0.bit`，640,108 字节，MD5 `e8655d781695708ecd2e9c83995a826e` |
| 资源占用 | LUT 11,392（58.12%）、寄存器 6,524（33.29%）、DSP 11（37.93%）、BRAM9K 27（42.19%）、PLL 3/4 |
| 全局时序 | SWNS −6.699 ns、STNS −1,476.518 ns |
| 像素域 | `video_clk → video_clk` SWNS +5.860 ns，4,330 个端点无建立违例 |
| 显示时序 | 640×480 有效区，800×525 总时序，约 59.524 Hz |
| 转场时长 | 64 帧（褪白 30 + 白场 4 + 淡入 30），约 1.075 s |

全局负余量的构成需要分开看：SDRAM DQ 接口的负余量属于约束缺失导致的接口假违例，`img_scaler` 的路径是真实组合延迟。像素域内部是干净的，这一点在报告里可以逐条核对。

> 历史阶段的时序与面积报告保留在 `doc/timing_rpt/`（E0~E4），那是优化过程的证据，数字与当前版本不同，引用时注意区分。

## 十、后续扩展方向

1. **真实音频**：将 `hdmi_audio_tone_i2s_64fs`（八音测试源）替换为 `rom/` 下的 I2S ROM 播放器，或改用 TF 卡 WAV 播放；后者需补文件解析、PCM 缓冲与采样率适配，并评估与图片加载共享 SPI 带宽时的仲裁。
2. **内容格式**：当前只播静态 BMP。加入 GIF / MJPEG 需要解码、连续供数与缓存管理，资源、时序和吞吐都要重新验证。
3. **网络接入**：加以太网或 WiFi 做内容更新与状态回传，属于信息发布终端的自然延伸。
4. **时序收敛**：当前全局 SWNS −6.699 ns，主要负余量集中在 SDRAM DQ 接口（接口约束缺失导致的假违例）和 `img_scaler` 的组合路径。前者补 `set_input_delay / set_output_delay` 即可转正，后者需继续加流水。
5. **交互扩展**：4×4 键盘尚余 KEY8~KEY15，可用于轮播间隔调节、画面冻结与预设参数档。
